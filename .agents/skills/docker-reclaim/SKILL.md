# Docker reclaim

Repeated local rebuilds pile up images and build cache. Pruning frees space inside Docker's disk, but on Windows the host drive gets it back only after that disk image is trimmed and compacted: a file of 300 GB can hold 15 GB of Docker data.

## Steps

1. **Report.** `node <this skill's folder>/reclaim.mjs report` prints the free space on the home drive, the date of the last prune, `docker system df` and, on Windows, the size of Docker Desktop's disk images, saying so when a disk image is far larger than what Docker uses (then compacting, not pruning, is what frees the space). If the engine does not answer within 15 seconds it says so and stops: tell the user to start Docker Desktop (or free some space first if the disk is what killed it), do not retry in a loop. `docker system df` itself may take up to two minutes on a big store.
2. **Prune, only when Docker's images or build cache are the cause.** `node <this skill's folder>/reclaim.mjs prune` runs the safe set only and prints the free space before and after and `docker system df` after: dangling images, unused images created more than 168 hours ago and build cache unused for that long (`--older-than 72h` to change it, 24h at the least: for images the filter goes by creation time, so less would take what was built today; build cache goes by last use). Stopped containers are kept, and so are the images they use, so a stopped compose stack stays intact. Run it without asking: it removes only what a rebuild or pull recreates. **It can take minutes**: run it with the shell's longest timeout or in the background, and read the summary it prints. It records the run when at least one step succeeded (none did: it exits non-zero and records nothing) (shown as "Last docker prune" by `report`). **If `report` shows a prune in the last 24 hours, do not prune again**: on Windows remind the user of `compact`, otherwise tell them nothing more is gained. On Windows it ends with a trim of the disk image (`wsl ... fstrim`, a warning if it fails).
3. **Compact (Windows).** `node <this skill's folder>/reclaim.mjs compact` prints the exact steps with the real paths. Give them to the user and stop: they need to quit Docker Desktop, run `wsl --shutdown` and use an Administrator PowerShell, which an agent cannot do. The steps trim first (`node <this skill's folder>/reclaim.mjs trim`, while Docker still runs), end the diskpart sequence with `detach vdisk` and check `(Get-DiskImage -ImagePath ...).Attached` prints False: a disk image left attached makes Docker fail to start. If space is still low after a prune that already ran, this is the step to remind the user of, not another prune. On macOS and Linux it says no step is needed.

## Never volumes

Local MongoDB and Redis data lives in Docker volumes. No `docker volume prune`, no `docker system prune --volumes`, no `docker container prune`, no Docker Desktop "Clean / Purge data", and no `docker volume rm` unless the user names that volume. The script has no such command; do not add one by hand. If volumes are the space hog, show the user `docker system df -v` and let them choose.
